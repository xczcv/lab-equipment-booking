# P01 · Локальна реалізація ЛР1–ЛР5

23 листопада 2026. Запит на реалізацію передано OpenAI Codex у повідомленні з технічним дорученням. Нижче збережено зміст одного запиту. Заголовки фрагментів додано для посилань. Службові заголовки, приватні шляхи й персональні дані вилучено.

## P01-scope

> Користувач доручив почати локальну реалізацію всіх п'яти послідовних лабораторних Node.js для одного проєкту. Реалізуй і перевір самостійно в наявному Git-репозиторії [вилучено приватний шлях і персональні дані]. Це твоє єдине місце для правок. Git-корінь уже налаштований і містить README. Матеріали в [вилучено приватний шлях]. Прочитай [вилучено приватний шлях]/AGENTS.md, README проєкту та п'ять оригінальних завдань у Labs. Інший студентський проєкт розробляється незалежно й не є вихідним кодом або джерелом рішень для цього. Проєкт про каталог приладів і бронювання готових слотів. Критичні сценарії: двоє паралельно бронюють слот, один дістає 409; ідемпотентний повтор; скасування і повторне бронювання; дата лабораторії Europe/Kyiv. Умова МКР окремо ще недоступна.

## P01-stages

> Виконай ЛР1–ЛР5 по порядку, з працездатними проміжними станами. Розділи історію на змістовні локальні коміти за зробленими змінами. Збережи окрему ревізію повного API на статичних даних перед PostgreSQL і чіткі межі лабораторних для подальших окремих PR. Обирай практичні інструменти й мінімальну архітектуру, достатню для оригінальних умов.

## P01-LR2

> Для ЛР2 зроби контекст ініціатора і business-process ID у всіх прикладних логах запиту, включно з операціями БД та результатами, перевір валідацію, транзакції, ідемпотентність, збої й N+1.

## P01-LR3

> Для ЛР3 потрібні відтворювані unit/integration/E2E й мутаційний прогін та класифікація мутантів.

## P01-LR4

> Для ЛР4 підготуй GitHub Actions, контейнер, міграції, перевірку готовності й /version, і перевір локально те, що можна відтворити.

## P01-LR1-LR4

> У ЛР1 та ЛР4 навмисний збій використовуй як явно позначений негативний тест hook або CI. Зафіксуй справжню команду й результат. Історію, результати й помилки не інсценуй.

## P01-LR5

> Для ЛР5 зроби справжні повторні виміри до і після й профілювання, EXPLAIN ANALYZE та виділення бібліотеки з типізованим контрактом і DI за даними, з прив'язкою до SHA.

## P01-submission

> Коміти дозволені локально. Залиш існуючі Git-налаштування та remote, не роби push, PR, змін у GitHub або публічного деплою без окремого доручення. Познач авторство й участь AI прозоро. Умова курсу вимагає, щоб студент погодив вимоги й інженерні рішення та власноруч підготував DEFENSE. Документуй запропоновані рішення як робочі та залиш висновки для захисту студенту, не пиши DEFENSE від його імені. Працюй без підлеглих агентів. Наприкінці дай локальні ревізії по лабораторних, реально виконані перевірки, місця доказів, стан робочої папки й конкретні кроки, що потребують GitHub/staging або матеріалів викладача.
