# ЛР2. Повний API і PostgreSQL

**Статус — чернетка для погодження студентом.**

Мета — відтворити однаковий HTTP-контракт на прототипі та PostgreSQL і зберігати бронювання атомарно.

## Критерії приймання

- До переходу на БД окрема ревізія `lab-02-prototype` надає каталог, пошук слотів, створення, історію та скасування. У цьому зрізі `npm run build && node --test test/prototype.test.js` проходить.
- У `lab-02` `npm run build && sh scripts/with-postgres.sh node --test test/postgres-contract.test.js` проходить на одноразовій PostgreSQL. Відсутній/невідомий ініціатор дає 401, невалідні параметри — 400, зайнятий слот — 409. Пошук повертає тільки вільні майбутні слоти календарного дня Europe/Kyiv.
- У конкурентних запитах на один слот має бути один успішний запис. Повтор того самого запиту з тим самим ключем повертає незмінну первинну відповідь. Повтор з іншим слотом дає 409. Після збою запису чека транзакція залишає нуль бронювань і чеків.
- У логах пошуку є рівно одна SQL-операція доступності, а рядки запиту, SQL та результату містять той самий business-process ID та ініціатора. `X-User-Id` на стенді використовується лише з тестовими ідентичностями.
