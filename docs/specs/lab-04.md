# ЛР4. CI і розгортання

**Статус — чернетка для погодження студентом.**

Мета — перевірити PR на ізольованій БД та розгорнути точний SHA на staging після проходження `quality`.

## Критерії приймання

- Локально `actionlint` приймає workflow. `make container-check` запускає структурні міграції контейнером. До окремого створення індексів `/ready` дає 503, після нього — 200. `/version` повертає SHA, переданий під час збірки.
- На GitHub обов'язкова перевірка `quality` охоплює subjects у всьому діапазоні PR, формат, лінт, збірку, тести, окрему PostgreSQL та збірку Docker. Демонстраційний PR із коректним subject та помилкою форматування дає червоний check і недоступне merge. Окремий коміт виправляє форматування, після чого `quality` переходить у зелений стан.
- Після merge зелений `quality` на `main` запускає job `staging`. У записі Render та у публічному `GET /version` має бути SHA цього push, а `GET /ready` має дати 200. Для CI доступна тільки одноразова БД.

Перший пункт має локальні докази. GitHub checks, блокування merge та публічний staging очікують окремого підтвердження.
