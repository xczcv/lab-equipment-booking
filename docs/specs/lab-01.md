# ЛР1. Основа сервісу

**Статус — чернетка для погодження студентом.**

Мета — зафіксувати межі застосунку й отримати відтворювану збірку з першим HTTP-маршрутом.

## Критерії приймання

- На ревізії `lab-01` команда `npm ci && make check` завершується з кодом 0. Smoke-тест запускає зібраний модуль і отримує з `GET /health` HTTP 200 та JSON `{"status":"ok"}`.
- `make hooks` встановлює `pre-commit` і `pre-push`. У виділеному локальному тесті навмисно неформатований файл дає код 1 під час `git commit`, а SHA HEAD до і після збігається. Для передавання іншої гілки як аргументу `git push` цільову ревізію слід перевірити окремо. Поточний `pre-push` перевіряє активний checkout.
- Документація визначає точку запуску, HTTP-шар, прикладні операції та сховище. Зафіксовано зв'язки «прилад — слот — бронювання — студент» і формат ADR та перевірок. У цьому зрізі виконується перевірка живого HTTP-процесу. Готовність БД перевіряється з ЛР4.
