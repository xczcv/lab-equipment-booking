# 3. CI та розгортання

Статус — запропоновано.

GitHub Actions перевіряє PR та коміти main з одноразовою PostgreSQL. Для staging розглянуто власну VM та керований Docker-сервіс. Пропозиція — GitHub Actions викликає Render API з конкретним SHA після зеленого main. Render збирає Dockerfile з цього SHA й очікує готовності нового екземпляра перед перенаправленням трафіку. GitHub Actions отримує тільки повноваження викликати Render API. База доступна контейнерам Render через приватне з'єднання.

Окрема команда Render pre-deploy готує структурні зміни та виконує індекси CONCURRENTLY. Запуск контейнера повторює тільки короткий структурний етап. Сумісні зміни схеми дають старій версії продовжити обробку трафіку. Демонстраційне наповнення запускається вручну. План Render має підтримувати pre-deploy і обраний регіон. Зовнішню конфігурацію та оплату має погодити власник.
